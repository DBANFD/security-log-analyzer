# Build and release

Windows x64 builds use Python 3.13.5 and the pinned PyInstaller tools. The GUI and CLI share a one-folder dependency bundle; neither requires Python on the destination machine. The source can run on other platforms, but no Linux/macOS executable is supplied in this release.

```powershell
py -3.13 -m venv work/build-venv
./work/build-venv/Scripts/python.exe -m pip install -r requirements-build.txt
./work/build-venv/Scripts/python.exe -m PyInstaller --noconfirm --clean --distpath work/frozen-dist --workpath work/frozen-build packaging/windows.spec
./work/frozen-dist/SecurityLogAnalyzer/security-log-analyzer-cli.exe --version
./work/build-venv/Scripts/python.exe tools/package_release.py --app-dir work/frozen-dist/SecurityLogAnalyzer --output dist --tag v0.3.0
```

The packager takes source files only from Git's tracked file list. Review `git ls-files` before packaging. It refuses obvious case/native-trace/private paths and adds only approved docs/samples/licenses to the application bundle. Generated case data and local project memory must never be tracked. Runtime files under `_internal` are required and must remain alongside both executables.

Pushing a version tag runs the release workflow: native fixture generation, all tests, Windows builds, frozen CLI smoke tests, source/binary packaging, checksums, then draft creation. Review CI, download and hash-check the draft assets, and exercise the downloaded binary before publishing. Tags must match the package version, and each version needs `docs/RELEASE-NOTES-vX.Y.Z.md`. Do not replace a published version's assets with different bytes.

GitHub's autogenerated source archives are also available, but the named source ZIP is included in SHA256SUMS alongside the portable Windows ZIP and synthetic HTML report. No signing key or certificate is configured; binaries are unsigned. Publishing a release does not change Windows security policies.
